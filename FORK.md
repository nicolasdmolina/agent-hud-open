All of the fork's changes live on the branch `fork`, which is the default branch here. `main` mirrors upstream and never carries fork commits. Pull requests target `fork`. Nothing is sent upstream.

## Hermes live channel

Design for tickets 12 to 16. The pure half is built (ticket 12). The connection is ticket 13.

### Shapes

All in `src/crates/agents/src/hermes/gateway/`, with no I/O and no clock.

- **Where something happens** (`identity.rs`). `GatewayId` names one gateway and stays the same across its restarts. `Profile` is `Default` or `Named`. `SessionRef` is gateway, profile and the gateway's session id. `hud_id()` gives `hermes:<id>` or `hermes:<profile>:<id>`, the same as the hooks and the `state.db` reader. Phase 2 adds gateways by adding `GatewayId`s; nothing assumes one.
- **Connection state** (`connection.rs`). `Disconnected`, `Connecting`, `Ready(Instance)`, `Unsupported(reason)`, `Failed(reason)`. `identify()` reads the control socket's answer with the checks Hermes's own client applies. A new `instance_id` is a restart.
- **Pending item** (`ask.rs`). `Pending` is a `SessionRef`, an `Ask` and an optional deadline. `Ask` is one of three types. `Question` has a prompt id, the turn's `execution_generation`, the text, the choices and whether several may be picked. `Approval` has a prompt id, the generation, the command, the description and only the choices Hermes offered. `Batch` is the set of questions Hermes sends as a request of its own (`clarify`, id `srq-…`) when the terminal UI started the turn. It has a request id and ordered questions, and no generation and no deadline.
- **Decision** (`decision.rs`). `Question::answer(Answer)`, `Approval::respond(Choice)` and `Batch::answer(answers)` are the only ways to build an answer, so an approval's choice cannot be put on a question. A doc test proves it does not compile. `Answer` cannot be empty. `Pending::reply(decision)` turns the HUD's `RequestDecision` into the exact frame. `allow` is `once`, `deny` is `deny`, `always` is `always`, and `always` with `suggestion: {type: "scope", scope: "session"}` is `session`.
- **Card** (`card.rs`). `Pending::view()` is the usual request view. An approval lists the lasting choices Hermes offers in `suggestions`, so a limited request shows once and deny alone.
- **State** (`state.rs`, `reduce.rs`, `readings.rs`, `effect.rs`). `Gateway::apply(Input, now_ms) -> Vec<Effect>`. Inputs are what happened: identify answered, a frame arrived, a list or a replay or a snapshot came back, an answer was sent or replied to, time passed. Effects are what to do: open a card, close it with the reason, show it again, list sessions, read a session, take a snapshot.

A card closes when Hermes says it settled, when its turn ends (only cards of that turn or an earlier one), when its own time runs out, when an answer comes back `already_resolved` or `stale_generation`, when a snapshot no longer lists it, when its session leaves the live list, and when the gateway restarts. A dropped socket closes nothing: the request still waits in Hermes and keeps its deadline.

### Shell hooks: kept

The hooks stay installed for running and finished. They are pushes that already work and are tested, and they are all there is for a gateway without the live connection (the Mini's 0.21.6 today). The live connection adds what hooks cannot: the text of a question and a way to answer. Holding a subscription on every session to replace the hooks would change how Nicky's sessions end and re-commit idle sessions' settings (ticket 11, answer 2).

### What ticket 13 must implement

The connection goes in `src/crates/platform/src/clients/hermes/`, started from `hooks::configure` when `clients::runs(&agents::hermes::GATEWAY)`. It owns one `Gateway` per gateway (`GatewayId::new("local")` in phase 1), feeds it every input and carries out every effect. It decides nothing else.

1. **Find the control socket from a Hermes home passed in.** `<home>/gateway.sock` (`CONTROL_SOCKET`). If that is missing, read `<home>/gateway.sock.path` (`CONTROL_POINTER`) and pass its text to `pointed_socket()`. Check that the home, the pointer and the socket are the user's own with no access for others, and that the listener is the same user. Production passes the resolved `HERMES_HOME`, else `~/.hermes`. Tests pass an isolated home with its own gateway. Never test against `~/.hermes`: adding a profile there rewrites Nicky's `config.yaml` (ticket 11, deviation 1). Resolve links in the home before calling `identify(answer, home)`, which compares it as written.
2. **Handshake.** Send `identify_line()`, one JSON line in and one out, and give the answer to the model as `Input::Identified`. Retry once on a timeout before `Input::Lost(Unreachable)`. On `Ready`, send `ticket_line(instance, Scope::Host)` (it has no `subject`), read the answer with `granted()`, and dial `ws://127.0.0.1:<instance.port>/api/ws` with `ticket.subprotocols()`, no `Origin` header and no proxy. Check the echoed subprotocol is `SUBPROTOCOL`. A refusal goes in as `Input::Denied`, HTTP 403 as `Input::Lost(TicketRefused)`. Allow frames up to 8 MiB.
3. **Tickets are never kept.** Mint, dial, drop. A ticket lasts 30 s and opens one socket. `Ticket` prints as `<masked>`; do not log the subprotocol list.
4. **Wait, do not fall back, while a gateway starts.** `Connecting` after `Identified::Wait` means ask again with backoff. `Unsupported` means stop and leave Hermes to the hooks; ask again rarely, since an update can add the connection. A draining gateway that waits for its turns (`instance.draining`) is `Ready` and can be answered.
5. **Cover every served profile.** One `active_list(profile, scope)` per entry of `instance.served`, each result in as `Input::Listed` with its profile. A host's list call covers one profile, not all. Skip a profile that answers `profile_mismatch` or `runtime_draining` this round.
6. **Poll; do not hold subscriptions.** List when the model says `Effect::List` (Hermes's `sessions.changed` and `platforms.changed` hints), when a Hermes hook reports a turn running or waiting, at startup and after every reconnect, and on a timer while any session works or waits or a card shows. Do each `Effect::Read` with `events_since(session, cursor, scope)` and give the result back as `Input::Replayed`. The model keeps the cursors. It starts a new stream at 0 in its epoch, never at the latest event.
7. **Take a snapshot only when asked, on a socket of its own.** `Effect::Resume` means the stream cannot say what waits. Open a second socket, send `resume()`, give the result as `Input::Resumed`, then `detach()` and close that socket. `session.resume` subscribes: it re-commits an idle session's settings, cancels a pending close, and keeps the session alive while the socket stays open. A waiting session is busy, so its settings are left alone.
8. **Answer on a short socket.** Take the decision with `Requests::checked`, build `pending.reply(decision, scope)`. `Ok(None)` is leave it. For `Reply::Call`: resume the session (an answer from a socket that is not subscribed is refused), send `call.frame(id)`, tell the model `Input::Sent`, give it the reply as `Input::Responded`, detach, close. For `Reply::Result` (a set of questions): resume, write the frame, `Input::Sent`. Nothing replies to it. The model closes the card on `request.cancel` or when a later reading no longer lists it, and says `Effect::Unanswered` if it is still listed 5 s later.
9. **Effects to core.** `Open(p)` is `register_native(p.id(), p.view(now), now)`. `Close { id }` is `settle_native(id)`. `Unanswered { pending, why }` is `settle_native` then `register_native` again, plus a failed delivery; after `PermissionDenied`, resume and send again. After any change call `set_native_waiting` with the sessions that have cards. One timer waits for `gateway.next_deadline()` and sends `Input::Tick`.
10. **Reconnect.** Socket closed or failed is `Input::Lost`. Back off, identify again every time, and do not expect the port to change after a restart. The model closes every card when the instance id changes. After a reconnect to the same instance, list at once.
11. **Never.** Write under a Hermes home. Send `end_reason` on detach, which would close Nicky's session. Answer or show a `sudo` or `secret` request. Hold the collection gate while waiting on the network.

Still to measure in ticket 13: whether listing every served profile plus the reads fits the one-second target, and whether Hermes's `on_human_input_request` hook should be installed as the push for questions (today's hooks push approvals only). Unproven against a real gateway: the `profile` parameter on calls other than the two list calls (Hermes's dispatch routes every method by it, `gateway/session_controls.py:280`), a JSON list as an answer inside a set of questions (`tools/clarify_tool.py`, `_clean_answer`), Telegram sessions, a real old gateway, and a draining one.

### For tickets 14 to 16

- 14: the card is `kind: "question"` with `answersQuestion`, one entry per question keyed by `answerKey`. No options means a typed answer.
- 15: read the lasting choices from `suggestions` and send `{kind: "always", suggestion}` for the one chosen. `allowsAlways` is true when Hermes offers session or always. `alwaysAllowRule` is the text to show for always, which writes a rule into the profile's `config.yaml`.
- 16: `gateway.statuses()` gives every live session as starting, working, waiting or idle. A session with a card here counts as waiting even where Hermes says `working`, which it does for a set of questions.

## Updating from upstream

Remotes: `origin` is this fork, `upstream` is the author's repo with pushing disabled.

1. Fetch both remotes: `git fetch upstream && git fetch origin`.
2. Fast-forward the fork's `main` to upstream: `git push origin upstream/main:main`. This must be a fast-forward. If it is refused, someone committed to `main`; move that commit to `fork` first.
3. Bring `fork` up to date by merging, not rebasing: `git checkout fork && git merge --ff-only origin/fork && git merge origin/main`, fix any conflicts, then `git push origin fork`. Merging keeps `fork` history stable, so open ticket branches built on it stay valid and no force push to a shared branch is needed.
4. Run the checks:

   ```sh
   pnpm install --frozen-lockfile
   pnpm run format
   pnpm run check
   pnpm run test
   pnpm run lint
   cargo test --workspace
   git diff --check
   ```

5. Rebuild and reinstall: `sh src/tooling/fork-install.sh`. It builds the bundle with the fork's overlay and `AGENT_HUD_HOOK_OWNER` set to the installed copy's executable (so its client hooks switch works), quits the running fork, replaces `/Applications/Agent HUD Fork.app` and opens it (`--no-open` skips that). It always builds in this checkout's own `target/`: a build folder shared between worktrees can reuse another worktree's crates.
